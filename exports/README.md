# exports/ — the A → B half of the cross-repo contract

`signal-feed.json` (schema `signal-feed/1`) is this repo's report corpus projected into
one machine-readable file, regenerated by `node tools/export-signals.mjs` and consumed by
the **personal-accounting** ledger, which stores it as a read model and eventually joins
realized P&L back to the score that authorized the trade.

Each signal also carries the additive `tagging` projection. Its `registry` is
`report-phase-registry/1`: one immutable exact tag and decision per applicable phase, with
the filename-derived asset/date/HHMM and report version. `FR-B` contains only 1A/1B/2;
FR channel `none` emits FR-A vocabulary. The registry is normalized by the accounting
consumer into signal-phase rows; it is not a fill-state or JSON attribution store.

```
node tools/export-signals.mjs             # regenerate (writes only if content changed)
node tools/export-signals.mjs --dry-run   # counts only, writes nothing
node tools/export-signals.mjs --strict    # exit 1 if a post-epoch report lacks a machine block
```

## Why this file is committed — and dated position snapshots are now retained too

They point in opposite directions and carry opposite risk.

`signal-feed.json` is derived **entirely from already-committed reports**. It discloses
nothing that is not already in the tree, so committing it is free, and it buys two things:
a git-diffable history of how each signal evolved, and a consumer that reads from a path
git keeps current instead of one that must run a tool first.

`position-snapshot-*.json` is the **B → A** direction and carries real account balances,
ACB cost basis, open futures positions and realized PnL. The personal-accounting export
writes a new UTC-dated file for every explicit export, and `tools/position.mjs` selects the
newest one from this directory. These files are intentionally retained in Git at the
user's request; **this repo auto-pushes every commit to a public remote**, so review the
remote visibility before committing or pushing a snapshot. Files are written mode `0600`
by the producer; preserve restrictive local permissions where possible.

## Two consequences of committing it

1. **Byte-stable serialization.** Object keys are sorted recursively, arrays keep their
   order, 2-space indent, trailing newline (`canonicalJSON` in `tools/lib.mjs`). An
   unstable key order would make every regeneration a whole-file diff.
2. **Skip-write-if-unchanged.** `generated_at` moves on every run by construction, so it is
   excluded from the comparison. A rerun that changes nothing else prints `unchanged` and
   leaves the file — and `git status` — untouched.

That skip-write rule belongs to `signal-feed.json`; dated position exports deliberately create a new
historical file for each explicit ledger export, even when the payload is otherwise unchanged.

## Encoding

Matching `position-snapshot/1`: **decimal quantities** — prices, scores, percentages, EV —
cross the boundary as **JSON strings in plain decimal notation**, because the consumer
stores them in `numeric(38,18)` / `numeric(4,1)` and a JS double cannot round-trip that.
**Counts, gate numbers, booleans and enums stay native**: they carry no round-trip risk and
stringifying them would only force every consumer to parse back.

## What the feed knows that a naive scan would get wrong

- **The filename is the primary key.** The machine block carries a `date` but no time field,
  and `(asset, framework, date)` genuinely collides — btc/eth × `fallen_knives` on both
  2026-07-14 and 2026-07-18. `report_file` is the PK throughout. `report_at_utc` is derived
  by interpreting the filename's `HHMM` in `America/New_York` and is emitted alongside
  `report_zone` and a derivation note, never baked into a bare instant.
- **Scan by filename, never by "contains a machine block."**
  `grep -l '```json machine' reports/*.md` returns **40** files, but only **39** are reports:
  `calibration_ledger.md` quotes the fence in prose. A grep-first scanner ingests the
  calibration ledger as if it were a signal. Ignored files are listed in `ignored_files[]`.
- **Channel B reuses Channel A's five leg keys for a different rubric.** So legs are emitted
  as an **ordered array of objects** carrying `ordinal` + `block_key` + `rubric_name` +
  `value` + `max`, under an explicit `rubric` discriminator (`FK/1` | `FR-A/1` | `FR-B/1`).
  There is no representation of this feed in which `euphoria` silently means rally extension.
- **Missing fields from an older epoch are resolved, not marked unknown.** A pre-2026-07-27
  Flying Rocket report has no `channel` because Channel B did not exist — so the feed emits
  `channel: "A"` with `channel_inferred: true` and a basis string. Likewise a missing
  `score.discretionary` predates the Analyst Discretion Layer, when discretion was
  structurally impossible: `0`, with `mechanical = raw`, both flagged inferred.
- **Legacy reports are skipped loudly, not silently.** 66 prose-only reports predate the
  machine-block epoch (2026-07-11). They appear in `skipped[]` with a reason, are counted in
  `counts.skipped_no_machine_block`, and are **expected** — `--strict` fires only when a
  report dated on/after the epoch lacks a block.

## `filled_tranche_count` is 0 on every pre-2026-07-29 signal

Not an observation — an artifact. Across 39 reports, **152/152** tranches encode `entry` as
prose (`"~65000 (MTM -1.2%)"`), and `deployed: true` appears **zero** times, so the fill
predicate was never once true. `report-machine/1` gained numeric `entry_price` and boolean
`deployed` on 2026-07-29 to fix exactly this; the caveat travels with the data in
`deployment.filled_detection_caveat`. Phase 4b's calibration join is gated on it, because
without a machine-visible fill the join degrades to timestamp-proximity guessing.
